# 答辩专有名词解释

本文用于答辩前快速统一术语口径。解释重点不是学术综述，而是说明这些词在 Better-MV-DUSt3R 项目中具体指什么、为什么会出现在 PPT 和讲稿里。

## 一、项目与基础模型

### Better-MV-DUSt3R

本组项目名称。它是基于 MV-DUSt3R 的工程优化项目，目标是把多视图三维重建流程整理成可运行、可测试、可复现的平台。项目重点不在重新设计主干网络，而在运行配置、输入质量评分、低显存推理、视图配对优化、全局优化早停、结果导出和实验验证。

### DUSt3R

一种学习式三维重建方法。它可以从图像对中预测三维点和置信度，相比传统 SfM/MVS，减少了手工特征匹配和多阶段几何流程的依赖。

### MV-DUSt3R

DUSt3R 的多视图扩展方向，用于处理多张图像之间的几何关系。本项目选择它作为基础，是因为它更贴近“多图输入到三维模型输出”的课程目标，同时保留全局对齐环节，方便做工程优化和测试。

### SfM / MVS

SfM 是 Structure from Motion，即从多张图像估计相机运动和稀疏三维结构。MVS 是 Multi-View Stereo，即多视图立体重建，用于得到更密集的三维结果。它们是经典几何路线，解释性强，但对特征匹配、光照、纹理和多阶段调参较敏感。

### NeRF

Neural Radiance Fields，神经辐射场。它擅长新视角合成，但通常需要训练或采样过程，直接导出 GLB/网格还要额外处理。本项目没有选择 NeRF，是因为课程目标更偏向多图重建、工程运行和结果导出。

## 二、系统流程相关术语

### 多视图三维重建

从多个视角的图像恢复三维结构。这里的“多视图”不是简单上传多张图，而是利用不同视角之间的对应关系、相机关系和几何一致性，生成点云或三维资产。

### 点云

由大量三维点组成的结果，每个点通常包含空间坐标，有时还包含颜色或置信度。点云更接近模型的原始三维输出，便于观察结构是否完整、是否漂移、是否稀疏。

### GLB

一种常见的三维资产文件格式，可以封装三维模型、颜色和材质信息，方便在查看器或网页中打开。本项目把 GLB 作为课程展示和结果归档的重要输出。

### Gradio Demo

项目的图形交互入口。用户可以通过网页界面上传图片或视频，查看重建结果。Demo 适合现场演示。

### CLI

Command Line Interface，命令行入口。本项目中的 `inference_global_optimization.py` 适合批量测试、固定参数复现和记录实验结果。

### Demo / CLI 统一口径

指 Demo 和命令行不是两套互相割裂的流程，而是共享相同的运行策略和输出逻辑。这样现场演示结果和批量测试结果可以互相印证。

## 三、输入质量与鲁棒性

### quality_score

输入图像质量分。项目中主要从清晰度、对比度和曝光异常等角度计算，用于判断图片是否可能影响重建。它把“图片有点糊”“光线太差”这类主观描述转成可记录的数值。

### raw_quality_score

原始质量分，通常表示图像加载阶段直接计算出的质量信息。后续可能经过归一化或策略处理，得到用于运行决策的 `quality_score`。

### Laplacian 方差

一种常见的清晰度估计方法。图像越清晰，边缘变化通常越明显，Laplacian 方差一般越大；图像越模糊，边缘变平，方差往往下降。本项目用它辅助判断模糊程度。

### 对比度

图像明暗差异程度。低对比度图片通常纹理不明显，会影响多视图几何关系的判断。

### 曝光裁剪

指大量像素接近纯黑或纯白，导致细节丢失。过曝和欠曝都会增加重建难度。

### preprocess_profile

预处理配置。它把图像加载、轻量增强和质量处理策略组织成统一入口，避免每次运行都手动调一堆参数。

### lite_robust_v1

本项目推荐的默认运行策略。它开启 AMP、轻量预处理、质量自适应阈值、OOM 回退、自动视图策略和全局优化早停。它不是理论最优配置，而是面向课程设备和答辩演示的稳妥默认方案。

### quality_adaptive

质量自适应策略。它根据输入质量调整置信度阈值等处理逻辑，让低质量输入不会完全按照干净输入的规则处理。

### adaptive threshold

自适应阈值。固定阈值对所有场景一刀切，自适应阈值会结合输入质量或置信度分布调整过滤标准。

### RGB corruption

训练或实验中对 RGB 图像加入扰动，例如模糊、低光照、压缩等，用来模拟真实低质量输入。

### corruption metadata

扰动元数据。记录某个样本被加了什么退化，方便后续分析低质量输入对结果的影响。

### geometry_loss_weight

几何损失权重。对于几何噪声较强的样本，下调与 GT 几何强相关的损失权重，避免模型被不可靠样本过度影响。

## 四、视图配对与推理效率

### pair

图像对。MV-DUSt3R 需要处理图像之间的关系，哪些图像组成 pair 会直接影响推理规模。

### complete graph

完整图策略，即所有图像两两配对。若有 n 张图，无向 pair 数约为 n(n-1)/2。24 张图约 276 个 pair，计算量和显存压力会迅速增加。

### scene graph

视图图结构。它描述哪些图像之间建立连接。不同 scene graph 会影响推理成本和全局结构稳定性。

### scene_graph_policy

视图图策略参数。项目中支持 `auto` 等策略，视图数量较少时可用完整图，数量较多时切换到 `anchorlocal-2`。

### anchorlocal

本项目中的视图配对优化策略。它选择高质量图像作为 anchor，同时保留局部相邻边。目的是减少冗余 pair，同时保留全局参照和视角连续性。

### anchorlocal-2

anchorlocal 的一种配置形式。可以理解为围绕 anchor 和局部邻接关系建立有限连接，避免 complete graph 的 pair 爆炸。

### 高质量 anchor

质量评分较高、适合作为全局参照的图像。它在 anchorlocal 中帮助维持整体结构。

## 五、低显存推理与运行配置

### AMP

Automatic Mixed Precision，自动混合精度。它在推理中使用较低精度计算来降低显存占用并提高吞吐，但需要避免关键损失或数值敏感部分不稳定。

### CUDA OOM

CUDA Out Of Memory，GPU 显存不足。多视图重建中，图像数量、分辨率和 pair 数都会导致 OOM。

### OOM retry

OOM 自动回退。系统优先用较大 batch 运行，若发生显存不足，则释放显存并降低 batch size 重试。项目中体现为从 batch=4 降到 2，再降到 1，尽量保证流程完成。

### pair_batch_size

每批处理多少图像对。较大 batch 通常吞吐更好，但显存压力更大；较小 batch 更稳，但可能更慢。

### runtime profile

运行配置档。把一组常用参数组合成一个可复用方案。本项目中 `lite_robust_v1` 是推荐默认配置。

## 六、全局优化与几何概念

### global optimization / GO

全局优化。成对预测只得到局部关系，全局优化负责把多个视图的结果对齐到统一坐标系中。

### global_alignment_loop

全局对齐迭代循环。它不断优化相机关系和三维结构，使多视图结果更一致。

### MST

Minimum Spanning Tree，最小生成树。在三维重建中可用于建立初始连接关系，让多视图对齐有一个较稳定的起点。

### PnP

Perspective-n-Point，根据三维点和二维图像点对应关系估计相机位姿的方法。它常用于相机姿态初始化或校正。

### min_iter

全局优化最少迭代次数。防止系统过早停止。

### check_every

每隔多少轮检查一次优化进展。用于判断 loss 是否还在有效下降。

### rel_tol

相对容忍度。如果 loss 的相对改善小于这个阈值，就认为改善不明显。

### patience

耐心次数。连续若干次检查都没有明显改善后，才触发早停，避免偶然波动导致过早停止。

### last_alignment_iterations

记录本次全局优化实际运行了多少轮。它让测试结果不只看最终模型，还能解释优化过程。

### 置信度

模型对预测结果可靠程度的估计。低置信度点通常会被过滤，否则可能造成点云噪声。

### 置信度过滤

根据置信度阈值去掉不可靠点。阈值过高会让点云变稀疏，阈值过低会保留更多噪声。

### 重投影误差

把三维点重新投影回二维图像后，与原图观测位置之间的像素偏差。误差越小，通常说明相机位姿和几何对齐越一致。本项目用它作为课程复现实验中的几何一致性指标。

## 七、测试与评价指标

### 课程复现实验

本项目中的测试口径。它不是公开 benchmark 排名，而是在固定环境、固定权重和统一运行配置下，比较不同输入组、运行策略和消融配置的相对表现。

### clean-turntable

干净转台场景。作为基础功能和精度基线，主要观察理想输入下系统能否稳定输出。

### desk-scene

桌面遮挡场景。用于测试局部遮挡、普通室内纹理和视角覆盖不完美时的稳定性。

### low-light

低光照输入。用于观察光照不足时质量评分、预处理和质量自适应策略是否能解释并缓解结果下降。

### mixed-noise

混合噪声输入。用于测试模糊、低光照、压缩或噪声叠加时系统是否仍能输出可检查结果。

### 成功率

成功完成重建并生成可检查输出的比例。这里的成功不只是程序没有报错，还包括 GLB、日志、截图等输出是否能用于展示和复查。

### 平均耗时

从开始执行重建命令到输出完成的端到端时间。它反映实际使用成本。

### 峰值显存

运行过程中 GPU 显存的最高占用。它反映系统对硬件的要求。

### 配对规模

本次运行构造了多少图像 pair。它直接影响推理耗时和显存压力。

### 全局优化迭代次数

全局优化实际执行的轮数。用于判断早停是否减少了无效迭代。

### 输出可辨性

输出 GLB、点云预览、置信度图、日志摘要是否能正常打开和检查。它是课程验收中很实用的结果检查指标。

### 消融实验

逐个关闭或替换某项优化，观察结果变化。它用于回答“到底是哪项改动带来了提升”，避免把所有提升笼统归因。

## 八、答辩中建议统一的边界说法

1. 本项目创新点是工程优化和课程复现实验闭环，不是提出新网络结构。
2. 测试数据是课程复现实验数据组，不宣称是大规模公开 benchmark。
3. 指标设计服务于课程验收：能否跑通、能否解释、能否复查、资源是否可控。
4. 低质量输入下结果下降是合理现象，项目目标是缓解和解释，不是完全消除。
5. GLB 输出强调展示和归档，点云与重投影误差更偏向算法结果分析。
